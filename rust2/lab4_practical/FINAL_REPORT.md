# Практична робота 4 — Інтеграція багтрекінгової системи

Проєкт: `rust2`
Виконавець: (вкажіть своє ім'я)

## Мета
Отримати практичні навички роботи із багтрекінговими системами, створити баг-репорти та зв'язати їх з PR/commit, виправити баги.

## Кроки виконання (коротко)
1. Обрати багтрекінг (GitHub Issues).
2. Підготувати приклади баг-репортів (файли в `lab4_practical/issues/`).
3. Створити issue у репозиторії (веб або API).
4. Створити гілки `fix/bug-001`, `fix/bug-002`, виправити код, зробити коміти і push.
5. Створити PR з описом `Fixes #<issue-number>` — після merge issue закриється.
6. Оновити звіт з посиланнями на issue та PR/commit.

## Виконані зміни (що має бути в репозиторії)
- `lab3/cli/src/main.rs` — виправлено форматування виводу тегів (join ", ").
- `lab3/core/src/store.rs` — створення батьківської директорії перед записом JSON.
- Приклади баг-репортів: `lab4_practical/issues/bug-001.md`, `lab4_practical/issues/bug-002.md`.

## Інструкції для викладача
1. Перевірити наявність issue і PR, які виправляють вказані баги.
2. Переконатися, що у PR вказано `Fixes #<issue-number>` або є посилання на коміт.
