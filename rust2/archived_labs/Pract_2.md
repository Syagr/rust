# Практична робота №2 — Звіт

Тема: Використання поліморфізму для абстрагування поведінки.

Мета: Отримати практичні навички застосування динамічного, статичного та поліморфізму у Rust.

## 2.1 Контрольні завдання

Реалізовано CLI-застосунок для індексування та класифікації файлів за тегами. Користувач може додавати файли з тегами та виконувати пошук за тегами через CLI-аргументи.

Приклад використання:

```
./filesindex add --path path/to/file --tags tag1,tag2,tag3
./filesindex get --tags tag1,tag2
```

Додано два варіанти збереження індексу: у JSON-файлі та у SQLite базі даних. Вибір бекенду зберігання здійснюється через змінну середовища `FILES_INDEX_PATH` у форматі `type:path`.

Приклади конфігурації:

```
FILES_INDEX_PATH=json:/home/user/.files_index.json
FILES_INDEX_PATH=sqlite:/home/user/.files_index.sqlite
```

Приклад `Cargo.toml` (залежності):

```
[package]
name = "filesindex"
version = "0.1.0"
edition = "2021"

[dependencies]
anyhow = "1"
clap = { version = "4", features = ["derive"] }
serde = { version = "1", features = ["derive"] }
serde_json = "1"
rusqlite = { version = "0.31" }
```

## Опис архітектури та поліморфізму

Для абстрагування поведінки збереження індексу використано trait `IndexStore` з двома реалізаціями: `JsonStore` та `SqliteStore`. В основному модулі програми вибір реалізації здійснюється динамічно на основі змінної середовища `FILES_INDEX_PATH`.

Динамічний поліморфізм реалізовано через `Box<dyn IndexStore>`, що дозволяє зберігати будь-яку реалізацію `IndexStore` за єдиним інтерфейсом та викликати методи `add`/`get` через vtable (динамічна диспетчеризація).

Можна було б застосувати статичний поліморфізм через generics (наприклад, `fn run<S: IndexStore>(store: S) -> Result<()>`), але в цьому завданні тип сховища визначається лише під час виконання (через env), тому зручно використовувати `dyn Trait`.

## Фрагменти реалізації

Trait (інтерфейс):

```
trait IndexStore {
    fn add(&self, path: &str, tags: &[String]) -> Result<()>;
    fn get(&self, tags: &[String]) -> Result<Vec<String>>;
}
```

Вибір бекенду через env:

Функція `make_store_from_env()` читає `FILES_INDEX_PATH`, парсить `type:path` та створює відповідний бекенд: `json` -> `JsonStore` або `sqlite` -> `SqliteStore`.

## 2.2 Контрольні питання

1) Чому статичний поліморфізм називають "абстракцією з нульовою вартістю" (zero-cost)?

 - Тому що при використанні generics (`S: Trait`) компілятор виконує мономорфізацію: для кожного конкретного типу `S` генерується спеціалізована версія коду. У результаті виклики методів можуть бути розв’язані під час компіляції (статична диспетчеризація) без vtable та без додаткових накладних витрат під час виконання.

2) Яка відмінність статичного поліморфізму від динамічного?

 - Статичний поліморфізм (generics) визначає конкретні типи на етапі компіляції, а виклики методів розв’язуються статично (без vtable).
 - Динамічний поліморфізм (`dyn Trait`) визначає конкретну реалізацію під час виконання, а виклики відбуваються через vtable (динамічна диспетчеризація).

3) У яких випадках неможливо використати `dyn Trait`?

 - `dyn Trait` неможливо використати, якщо trait не є object-safe. Типові причини:
   - методи, що повертають `Self` (наприклад, `fn clone(&self) -> Self` без спеціальних обхідних рішень);
   - методи з generic-параметрами (`fn foo<T>(&self, t: T)`);
   - використання `Self` у позиції параметра, що потребує знання конкретного розміру типу;
   - вимога `Sized` без можливості її прибрати (`trait Foo: Sized`).

4) Чим відрізняється поведінка пам'яті при передачі `T` та `&dyn T` у функцію?

 - Передача `T` (де `T: Trait`) у generics: у функцію передається конкретний тип із відомим розміром. Зазвичай це або значення на стеку (move), або оптимізований варіант згідно ABI. Виклики методів статично відомі.
 - Передача `&dyn Trait`: це "fat pointer" — пара (data pointer + vtable pointer). Розмір `&dyn Trait` визначений (вказівник + vtable), а виклики методів виконуються через vtable. Сам об'єкт може знаходитися будь-де (стек/купа), але посилання завжди містить вказівник на дані.

## Висновок

У практичній роботі реалізовано CLI-утиліту індексування файлів за тегами з двома бекендами збереження (JSON та SQLite). Для абстрагування поведінки використано trait `IndexStore` та динамічний поліморфізм через `Box<dyn IndexStore>`, що дозволяє обирати реалізацію під час виконання на основі змінної середовища.
