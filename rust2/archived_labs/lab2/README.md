# Практична робота 2 — Files index CLI

Проєкт знаходиться в `rust2/lab2`.

Опис: CLI `filesindex` дозволяє додавати файли з тегами та шукати файли за тегами. Підтримуються два способи збереження індексу: `json` та `sqlite`.

Конфіг: вкажіть змінну середовища `FILES_INDEX_PATH` у форматі `type:path`.
- `json:C:\path\to\index.json`
- `sqlite:C:\path\to\index.sqlite`

Приклади:

PowerShell:

```powershell
setx FILES_INDEX_PATH "json:C:\Users\me\.files_index.json"
$env:FILES_INDEX_PATH = "json:C:\Users\me\.files_index.json"

# додати файл
cargo run --manifest-path lab2\Cargo.toml -- add --path C:\Images\photo.jpg --tags cat,holiday

# знайти файли з тегом cat
cargo run --manifest-path lab2\Cargo.toml -- get --tags cat
```

Відповіді на контрольні питання (2.2):

- Чому статичний поліморфізм називають "абстракцією з нульовою вартістю"?
  - Тому що компілятор розгортає generic-код (часткове інстанціювання) під час компіляції і не додає додаткового часу виконання чи розміру на рівні виконуваного коду порівняно зі спеціалізованою імплементацією.

- Яка відмінність статичного поліморфізму від динамічного?
  - Статичний (generics) вибирається під час компіляції і часто інлайниться, тоді як динамічний (`dyn Trait`) використовує віртуальну таблицю (vtable) та виклики через інтерфейс під час виконання.

- У яких випадках неможливо використати `dyn Trait`?
  - Коли потрібна конкретна інформація про тип на етапі компіляції (наприклад, розмір у стеку), або коли trait має методи з `Self` у сигнатурі, які неможливо привести до об'єкта, або коли потрібна універсальна константна параметризація.

- Чим відрізняється поведінка пам'яті при передачі `T` та `&dyn T` у функцію?
  - `T` (конкретний тип) передається за значенням або за посиланням у залежності від сигнатури; розмір і розташування відомі компілятору. `&dyn T` — це fat pointer (ваговий вказівник) який містить вказівник на дані і вказівник на vtable; доступ до методів здійснюється через vtable і виклики не інлайняться.
