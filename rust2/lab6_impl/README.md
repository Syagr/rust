Lab 6 — Імплементація власних примітивів синхронізації

Розташування: `rust2/lab6_impl`

Що є в проєкті:
- `src/lib.rs` — реалізація `MyArc<T>` та `MyMutex<T>` (спрощені, пояснення в коді).
- `src/main.rs` — простий бенчмарк, який порівнює `std::sync::Arc`+`Mutex` та `MyArc`+`MyMutex`.

Запуск бенчмарка:

```bash
cd C:/It/projects/rust/rust2/lab6_impl
cargo run --release -- <threads> <increments>
# приклад: cargo run --release -- 8 50000
```

Miri (перевірка на UB):

1. Встановіть `miri`: `rustup component add miri` і `cargo miri setup`.
2. Запустіть у debug: `cargo miri run -- <threads> <increments>` (але Miri повільний і не рекомендується для release-бенчмарку).

Примітки:
- Реалізації спрощені (spinlock для mutex, атомарний лічильник для Arc). Для реального використання рекомендується використовувати `std` або `parking_lot`.
- Переконайтеся, що бенчмарки запускаються у release (`--release`) для більш реалістичних результатів.

Контрольні питання (коротко):
- Що таке атоміки? — типи та операції, що гарантують атомарність виконання (без переривань), наприклад `AtomicBool`, `AtomicUsize`.
- Що таке memory ordering? — порядок видимості атомарних операцій між потоками (Relaxed, Acquire, Release, AcqRel, SeqCst).
- Чим відрізняються різні memory ordering? — різні гарантії щодо упорядкування та бар'єрів: `Relaxed` — тільки атомарність; `Acquire`/`Release` — встановлюють бар'єри для читання/запису; `SeqCst` — найсуворіший глобальний порядок.
