Практична робота 7 — Web-downloader (асинхронні задачі)

Розташування: `rust2/lab7_web_downloader`

Опис програми

CLI:

```bash
# використання
cargo run --release -- --max-threads=8 urls.txt
# або читати зі stdin
cat urls.txt | cargo run --release -- --max-threads=8
```

Параметри:
- `--max-threads` — максимальна кількість одночасних асинхронних задач (якщо відсутній — кількість ядер CPU).
- `<file>` — файл зі списком URL по одному в рядку; якщо відсутній, читаємо зі stdin.

Результат: сторінки збережуться у папку `out/` з іменами `out/<sanitized_url>_<index>.html`.

Як це працює (коротко):
- Використано `tokio` (асинхронний рантайм, multithread) і `reqwest` як HTTP клієнт.
- Обмеження паралелізму реалізовано через `tokio::sync::Semaphore`.

Контрольні питання — коротко

1) Що таке асинхронне виконання?
- Асинхронне виконання означає, що програма може почати операцію (наприклад, I/O), не блокуючи потік, і продовжити інші задачі, доки операція не завершиться. В Rust це реалізовано через `Future`-и, які повертають результат у майбутньому.

2) Чому погано блокувати потік під час асинхронного виконання?
- Блокування потоку (наприклад `std::thread::sleep` або синхронний I/O) знижує ефективність рантайму: worker-потоки не можуть виконувати інші задачі, що призводить до зниження паралелізму і продуктивності.

3) Для чого існує трейт `Future`?
- `Future` описує значення, яке буде доступне пізніше. Трейт надає метод `poll`, який виносить виконання далі, та дозволяє runtime або екзекутору опитувати виконання задачі.

4) Чому існує `Pin` та `Unpin`?
- `Pin` гарантує, що об'єкт не буде переміщений у пам'яті — це важливо для `Future`-ів, що містять self-referential дані (посилання на власні поля). `Unpin` означає, що тип можна безпечно перемістити.
