Практична робота 7
Тема: Імплементація примітивних асинхронних задач у Rust

Мета: Навчитися працювати із асинхронними задачами в Rust, зрозуміти модель виконання, трейт `Future` та роль `Pin`/`Unpin`.

Інструкції
- Команда запуску: `cargo run --release -- --max-threads=<число> <file>`.
- Якщо `--max-threads` відсутня — використовується кількість ядер CPU.
- Якщо `<file>` відсутній — список URL читається зі stdin (по одному рядку).
- Результат: кожна сторінка зберігається у теку `out/` як `<санітайзед>_<індекс>.html`.

Контрольні питання — відповіді

1) Що таке асинхронне виконання?
Асинхронне виконання дозволяє задачам (tasks) описувати роботу, яка може бути призупинена (await) у точках, де чекають на зовнішні події (I/O, таймери тощо), і потім відновлена пізніше без блокування потоку. Це дозволяє ефективніше використовувати обчислювальні потужності, виконуючи інші задачі під час очікування.

2) Чому погано блокувати потік під час асинхронного виконання?
Блокування потоку (наприклад, великою обчислювальною задачею або синхронним I/O) перешкоджає виконанню інших асинхронних задач на тому самому потоці, знижуючи пропускну здатність рантайму і викликаючи деградацію продуктивності та високий латентний час. Асинхронні рантайми розраховані на велику кількість легковагових задач, які кооперативно передають керування; блокування порушує цю модель.

3) Для чого існує трейт `Future`?
Трейт `Future` описує об'єкт, який представляє значення, що буде доступне пізніше. Він надає метод `poll`, який викликає виконавець (executor) для просування обчислення до наступної точки очікування або завершення. `await` є синтаксичним цукром над роботою з `Future`.

4) Чому існує `Pin` та `Unpin` в Rust?
`Pin` гарантує, що дані не будуть переміщені в пам'яті — це критично для `Future`-об'єктів, які містять самопосилання (self-referential). Деякі фьючери або внутрішні буфери зберігають вказівники на себе; переміщення таких об'єктів порушить такі вказівники. `Unpin` є маркером, що означає, що тип безпечний для переміщення; `Pin` працює разом із цими маркерами, щоб забезпечити безпечний доступ.

Додаткові зауваження
- У реалізації цього проекту читання списку URL робиться блокуючим способом перед запуском рантайму, що для CLI-програми є допустимим і простим варіантом. Якщо потрібно повністю неблокуючу поведінку (наприклад, у серверному процесі), слід використовувати асинхронний ввід/вивід у межах рантайму.
- Для покращення робастності можна додати таймаут на запити (`reqwest::Client::builder().timeout(...)`), повтори (retries), та логування помилок.
